# Olympiad Platform

Мини-платформа для подготовки к олимпиадам по математике и информатике.
Пользователь регистрируется, вводит ответ на задачу, получает «Верно» или
«Неверно» и видит свои баллы, решённые задачи и историю всех попыток.

## Быстрый запуск на Windows / в PyCharm

Нужен **Python 3.11 или новее**, без верхнего ограничения версии.
Проверено на Python 3.13. При создании проекта в PyCharm выберите подходящий
интерпретатор в **Settings → Python Interpreter**. Если окружение уже создано
на Python 3.8, создайте новое на Python 3.11+; удалять старый Python не нужно.

Откройте терминал в папке проекта и выполните **две команды**:

```powershell
python -m pip install -r requirements.txt
python main.py
```

Первая команда устанавливает проект и библиотеки, вторая запускает сайт.
`requirements.txt` — файл установки зависимостей, а `README.md` — эта инструкция.
На неподходящей версии Python установщик и приложение выводят требование
**Python 3.11 или новее**, вместо запуска несовместимого приложения.

Откройте **http://127.0.0.1:5000**. Создайте аккаунт на странице регистрации.
Email не требуется. Логин: 3–32 символа; пароль: 8–128 символов.
Логины сравниваются без учёта регистра.

### Если нужно создать окружение вручную

Посмотрите установленные версии командой `py -0p`. Ниже пример для Python 3.13;
если установлена другая подходящая версия, замените 3.13 её номером.
Выполните команды из каталога проекта:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip --isolated install --index-url https://pypi.org/simple -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если `py` не видит Python, используйте путь к установленному `python.exe`.
Например, для стандартной установки Python 3.13 текущего пользователя:

```powershell
& "$env:LOCALAPPDATA\Programs\Python\Python313\python.exe" -m venv .venv
```

Остальные команды установки и запуска остаются теми же. Если `.venv` уже
создано на Python 3.8, создайте другое окружение, например `.venv313`, и используйте
это имя во всех командах. В PyCharm выберите соответствующий интерпретатор
`<папка проекта>\.venv313\Scripts\python.exe` в настройках Python Interpreter.

Версию можно проверить без установки библиотек:

```powershell
python check_python.py
```

Наличие нескольких версий Python не мешает работе: важна версия выбранного
интерпретатора. Установка нового Python не обновляет старое виртуальное окружение.

## Запуск на Linux / macOS

```bash
python3 check_python.py
python3 -m venv .venv
.venv/bin/python -m pip --isolated install --index-url https://pypi.org/simple -r requirements.txt
.venv/bin/python main.py
```

Если проверка сообщает о версии ниже 3.11, выберите подходящий установленный
интерпретатор (например, `python3.13`) и используйте его для создания окружения.

Сервер запускается через Waitress без отладчика. По умолчанию он доступен
только на этом компьютере. Остановить: Ctrl+C. Для повторного запуска
достаточно последней команды. База и ключ сессий сохраняются автоматически.

## Возможности и правила

- Каталог с тремя уровнями сложности, звёздами у названий задач и русскими
  названиями категорий. Фильтры работают мышью и клавиатурой; без JavaScript
  доступны обычные списки и кнопка «Применить».
- В новой базе автоматически создаются **23 готовые задачи** — полный каталог
  по математике, строкам и массивам. Готовая база для запуска не нужна:
  начальные задачи входят в исходники и создаются один раз.
- Первый вход на сайт и выход из аккаунта открывают полноэкранную страницу
  авторизации. Для HTML-страниц требуется вход; публичный каталог JSON API
  остаётся доступен. Вход и регистрация оформлены как две вкладки.
- Успешная регистрация через сайт сразу создаёт сессию и открывает главную.
  Обычный вход также ведёт на главную. API регистрации по-прежнему создаёт
  аккаунт без входа: после него нужен отдельный `POST /api/login`.
- В шапке сайта и на форме входа есть две видимые кнопки «Светлая» и «Тёмная»,
  в том числе на телефоне. Выбор сохраняется в браузере между страницами, выходом и
  повторным входом. Пока тема не выбрана вручную, используется настройка системы.
- Интерфейс занимает ширину окна: адаптивная сетка задач, активная вкладка
  в навигации, отдельные блоки условия, исходных данных и отправки ответа.
- Проверка текстового ответа выполняется только на сервере. Пробелы и
  переносы строк нормализуются; регистр букв учитывается. Формулы и код
  не вычисляются. Правильный ответ отсутствует в HTML и публичном API.
- Первое правильное решение каждой задачи даёт **ровно 1 балл** независимо
  от сложности. Повторные правильные решения записываются в историю без балла.
- Каждая принятая к проверке отправка сохраняется: задача, введённый ответ,
  результат и время. Пустые, некорректные и заблокированные запросы не являются
  попытками решения и не попадают в историю.
- Личный кабинет и история доступны только владельцу аккаунта. История
  разбита на страницы по 20 записей; старые попытки не удаляются.
- Даты в интерфейсе отображаются по московскому времени (МСК), например
  «18 октября 2026, 12:57». В базе и API даты остаются в UTC.
- Подписи счётчиков на главной и в профиле автоматически склоняются:
  «1 задача», «2 задачи», «5 задач», «1 балл», «2 балла», «5 баллов».
- Таблица лидеров содержит всех зарегистрированных пользователей, включая
  пользователей без баллов. Сортировка: баллы по убыванию, затем логин.
- База SQLite хранит пользователей, задачи, попытки и уникальные решения.
  Перезагрузка страницы, выход и перезапуск сервера не сбрасывают прогресс.

## Начисление баллов и защита

Баллы вычисляются как количество строк в `solves` для текущего пользователя.
Отдельного изменяемого счётчика нет. Первичный ключ `(account_id, problem_id)`
не допускает повторного решения. Попытка и запись о первом решении сохраняются
одной транзакцией `BEGIN IMMEDIATE`. Это работает при одновременных запросах
в нескольких потоках и процессах.

Идентификатор пользователя берётся из подписанной сессии. API не принимает
`points`, `user_id`, `correct`, `is_admin` и другие дополнительные поля для
начисления баллов. Пароли хешируются scrypt. Все изменяющие запросы требуют
CSRF-токен. Сессия обновляется при входе, выход выполняется только POST-запросом.
Текст в шаблонах экранируется; подключён CSP. Запуск пользовательского Python
и старые WebSocket/PvP-обработчики удалены из приложения.

Ограничения частоты хранятся в базе: регистрация — 20 запросов/IP в час,
вход — 50 запросов/IP и 15 запросов/логин за 15 минут, ответы — 120 запросов
на пользователя в минуту. При превышении возвращается HTTP 429 и `Retry-After`.
Размер запроса ограничен 64 КиБ, ответ — 2000 символами.

Подходы к [защите сессий и CSRF](https://flask.palletsprojects.com/en/stable/web-security/)
соответствуют документации Flask. Для HTTP-сервера используется
[Waitress](https://docs.pylonsproject.org/projects/waitress/en/stable/).

## Данные предыдущей версии

Если рядом с `main.py` уже есть прежняя `database.db`, при первом запуске:

1. Создаётся резервная копия SQLite в `backups/legacy-*.db`.
2. Пользователи переносятся в `accounts`; обычные пароли продолжают работать.
3. Старые задачи преобразуются в задачи с ответом для конкретного набора
   входных данных. Примеры правильных ответов на клиент не передаются.
4. История отправленного кода переносится с пометкой «решение на Python».
   Код хранится как текст и никогда не выполняется.
5. Каждая ранее решённая задача даёт один балл. Старый рейтинг и PvP-бонусы
   в новые баллы не преобразуются.
6. Старые таблицы остаются в базе как архив. Приложение их больше не использует.

Миграция транзакционная и выполняется один раз. Задачи с повреждёнными или
пустыми тестами остаются только в старых таблицах вместе со связанными данными.
При конфликте старых логинов без учёта регистра второй получает суффикс с ID.
Готовые задачи сохраняются при очистке старой истории.

Административных ролей, админ-панели и команды `create-admin` в приложении нет.
При обновлении версии 1 создаётся резервная копия `backups/before-remove-admin-*.db`,
затем из действующей платформы удаляется старый служебный аккаунт `admin`
вместе с его попытками и баллами. Обычные пользователи, их история и баллы
сохраняются. Другие прежние административные аккаунты становятся обычными.
При импорте первоначальной базы служебный аккаунт не переносится.

Для локального восстановления доступа пользователя остаётся команда:

```powershell
.\.venv\Scripts\python.exe -m flask --app main reset-password student
```

Новый пароль вводится интерактивно. Предыдущие сессии пользователя отзываются.

Перед изменением этой версии также сохранена локальная копия исходников и базы
в `backups/before_backend_2026-10-18/`. Резервные копии, база и секреты исключены
из Git: их нельзя публиковать вместе с исходниками.

### Очистка истории предыдущей версии

Команда удаляет перенесённые попытки с Python-кодом и неиспользуемые таблицы
`users`, `tasks`, `submissions`, `user_progress`, `pvp_matches`. Аккаунты,
текущие задачи и новые текстовые ответы сохраняются. Баллы пересчитываются
по первым правильным ответам из оставшейся истории.

Перед удалением команда автоматически сохраняет полную копию SQLite
в `backups/before-cleanup-legacy-*.db`. Запускайте при остановленном сервере:

```powershell
.\.venv\Scripts\python.exe -m flask --app main cleanup-legacy
```

Обычный запуск приложения историю не очищает. Для восстановления остановите
сервер и замените рабочую `database.db` выбранной резервной копией, предварительно
сохранив текущую базу и убрав её файлы `database.db-wal` и `database.db-shm`,
если они остались после остановки.

## API

Используется cookie-сессия. Сначала получите `GET /api/csrf`, сохраните cookies
и передавайте возвращённый `csrf_token` в заголовке `X-CSRF-Token` каждого POST.
Тело POST — JSON с `Content-Type: application/json`. После входа используйте
новый токен из ответа: старый аннулируется.

| Метод и маршрут | Данные / результат |
| --- | --- |
| `GET /api/csrf` | CSRF-токен, доступен до входа |
| `POST /api/register` | `{"username":"student","password":"long-password"}` |
| `POST /api/login` | Логин и пароль; возвращает профиль и новый CSRF-токен |
| `POST /api/logout` | `{}` |
| `GET /api/tasks` | Каталог без ответов; фильтры `difficulty=1/2/3`, `category` |
| `GET /api/tasks/1` | Условие задачи и собственный статус решения, после входа |
| `POST /api/tasks/1/submit` | `{"answer":"ваш ответ"}` |
| `GET /api/me` | Только собственные баллы, статистика и решённые задачи |
| `GET /api/history?page=1` | Только собственная история |
| `GET /api/leaderboard` | Логины и баллы всех пользователей |

Результат проверки: `attempt_id`, `correct`, `result`, `points_awarded`, `points`.
Эталонный ответ не возвращается даже после неправильной попытки.
Успешная регистрация и сохранённая попытка: 201; неверные данные: 400;
нет авторизации/неверный пароль: 401; нет прав: 403; отсутствующая задача: 404;
занятый логин: 409; слишком большой запрос: 413; неверный тип тела API: 415;
ограничение частоты: 429.

## Настройки без изменения исходников

| Переменная окружения | Значение по умолчанию |
| --- | --- |
| `HOST` | `127.0.0.1` |
| `PORT` | `5000` |
| `DATABASE_PATH` | `database.db` рядом с `main.py`; относительный путь считается от каталога проекта |
| `SECRET_KEY` | Автоматически создаваемый постоянный ключ в `instance/secret.key` |
| `COOKIE_SECURE` | `0`; установите `1` при доступе через HTTPS |

Например, другой порт в PowerShell: `$env:PORT = '5001'`, затем обычный запуск.
Для размещения вне локального компьютера настройте HTTPS перед Waitress и
`COOKIE_SECURE=1`. Не передавайте доступ к каталогу базы и секретов посетителям.
В `SECRET_KEY` можно передать случайную строку длиной не менее 32 символов.
Не удаляйте `instance/secret.key` при обычном перезапуске.

## Проверка

Результаты финальной проверки по всем разделам ТЗ: [ACCEPTANCE.md](ACCEPTANCE.md).
Текущий набор содержит 28 тестов, включая все 23 стартовые задачи и проверку версии Python.

Список ручных проверок для последнего обновления:

1. Войти в прежний аккаунт: новые текстовые ответы остались, попыток с пометкой
   «Перенесено: решение на Python» нет. Баллы равны числу уникальных задач
   с правильными текстовыми ответами; прежние баллы за код исчезли.
2. Открыть профиль, историю и страницу задачи: даты имеют вид
   «18 октября 2026, 12:57», рядом указано МСК. Время соответствует московскому.
3. Проверить подписи счётчиков на главной и в профиле при значениях 0, 1, 2, 5,
   11, 21, 22, 25: окончания меняются; у процента стоит «Доля верных ответов».
4. Решить задачу правильно и неправильно, затем повторить правильный ответ:
   история пополняется, повторное решение не добавляет балл.
5. Выйти, войти и перезапустить сервер: новые ответы и баллы сохраняются,
   удалённая история не появляется снова. У другого аккаунта собственная история.
6. Скачать репозиторий в отдельную папку и запустить по инструкции:
   создаётся чистая база с 23 задачами, без чужих аккаунтов и секретов.
7. В приватном окне браузера открыть главную, каталог или профиль: появляется
   полноэкранный вход. Переключиться на регистрацию, создать аккаунт, войти,
   выйти: снова отображается вход. Неверный пароль и занятый логин показывают
   сообщение в форме.
8. Переключить все вкладки: текущая выделена; на странице отдельной задачи
   выделен каталог. Проверить оформление на телефоне и широком мониторе:
   меню доступно, таблицы прокручиваются, панель ответа не перекрывает условие.
9. После регистрации проверить автоматический вход и переход на главную.
   Выйти и войти обычным способом: снова открывается главная.
10. Переключить тему, перейти по всем вкладкам, открыть задачу, выйти из
    аккаунта и обновить страницу: тема сохраняется. Проверить читаемость
    условий, форм, результатов попыток, фильтров и рейтинга в обеих темах.

Автоматические тесты можно запустить самостоятельно:

Чтобы вручную проверить первый запуск с 23 задачами, не затрагивая текущих
пользователей, откройте новый PowerShell в папке проекта и запустите отдельную базу:

```powershell
$env:DATABASE_PATH = 'instance/manual-fresh.db'
$env:PORT = '5001'
.\.venv\Scripts\python.exe main.py
```

Откройте **http://127.0.0.1:5001**, зарегистрируйтесь и проверьте каталог.
Это отдельная база: текущая `database.db` и прогресс в ней сохраняются.
Для обычного запуска используйте другое окно PowerShell без этих переменных.

Команда для автоматических проверок:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют отдельные временные базы и не меняют рабочие данные.
Проверяются регистрация двух пользователей, ошибки входа, текстовые ответы,
повторные и параллельные отправки, разделение данных, история, лидеры,
подделка параметров, CSRF, XSS, миграция, архивация задач, отзыв сессий, удаление старой административной роли,
сохранность после перезапуска и работа настоящего HTTP-сервера Waitress.
